#### 1. Production provider

Production uses:

```dotenv
AI_PROVIDER=groq
GROQ_MODEL=llama-3.3-70b-versatile
AI_PROVIDER_TIMEOUT_MS=120000
```

`GROQ_API_KEY` exists only inside the SSM SecureString and is loaded by EC2 at bootstrap. The frontend never receives the key or calls Groq directly.

#### 2. AI APIs

| API | Access | Function |
| --- | --- | --- |
| `POST /api/ai/chat` | authenticated user | Lesson-context Q&A |
| `GET /api/ai/history` | authenticated user | Retrieve chat history |
| `DELETE /api/ai/history` | authenticated user | Delete chat history |
| `POST /api/ai/summarize-lesson/:lesson_id` | course access | Read/create a document summary |
| `POST /api/ai/generate-quiz` | tutor | Generate questions by lesson and difficulty |

Students can use only active-enrollment course context. Tutors can index, regenerate summaries, and generate quizzes; the backend validates lesson-to-course relationships rather than trusting client IDs.

#### 3. Bound context

```dotenv
AI_CHAT_CONTEXT_MAX_CHARS=7000
AI_SUMMARY_CONTEXT_MAX_CHARS=9000
AI_QUIZ_CONTEXT_MAX_CHARS=8000
```

The backend selects relevant passages instead of sending an entire document. Chat includes only recent messages, while quiz prompts include difficulty to distinguish basic, intermediate, and advanced questions.

#### 4. Summary caching and quiz validation

A summary persists:

* Source `document_key`, model ID, and generation time.
* Input/output token counts and stop reason.
* `processing`, `ready`, or `failed` status.

Students read the stored summary; only tutors can force regeneration. Quiz responses must pass the structured parser, required count, option shape, and JSON/Boolean answer validation before becoming drafts. Tutors review drafts before saving them.

#### 5. Rate limits and error handling

```dotenv
AI_RATE_LIMIT_REQUESTS=10
AI_RATE_LIMIT_WINDOW_MS=60000
```

The per-user limit is persisted in MongoDB, so two backend instances do not double the quota. Exceeding it returns `429 AI_RATE_LIMITED` with `Retry-After`.

Provider errors are normalized:

| Code | HTTP | Meaning |
| --- | --- | --- |
| `AI_THROTTLED` | 429 | Groq quota/rate exceeded |
| `AI_TIMEOUT` | 504 | Provider timeout |
| `AI_CREDENTIALS_ERROR` | 503 | Missing or invalid API key |
| `AI_SERVICE_UNAVAILABLE` | 503 | Provider temporarily unavailable |
| `AI_INVALID_STRUCTURED_RESPONSE` | 502 | Invalid quiz structure |

#### 6. Track model and token usage

`AIMessage` stores `model_id`, input/output and total token counts, and stop reason. The AI Assistant displays model/token metadata; this supports cost estimation, usage monitoring, and troubleshooting.

Full prompts, API keys, and sensitive data are not written to CloudWatch logs.
